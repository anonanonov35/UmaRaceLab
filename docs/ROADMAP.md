# Развитие до точного симулятора

## Первый срез — выполнен

- Статическая разведка установки и базы, запись хешей файлов.
- Ограниченное чтение стандартной IL2CPP metadata v31, карта race-символов.
- Приложение Windows, редактор билдов, справочник навыков, выбор условий.
- Повторяемый экспериментальный прогон, 2D-схема, события, результаты и экспорт.
- Инструмент сравнения с эталонными JSON-трассами и проверки ядра.

## Восстановление механики — приоритет

1. Связать метаданные с нативными методами. Не повторять без изменения подхода неудачный поиск регистраций в Il2CppDumper и Cpp2IL.
2. Найти константы реального шага, стартовой задержки, фаз, HP и финиша; подтвердить тела базовых калькуляторов.
3. Разобраться с `RaceSimulateData` и сериализацией доступного локального повтора. Не предполагать, что серверные DebugRace API доступны пользователю.
4. Добавить первый эталон «один участник, без навыков», затем несколько разных статов/стратегий. Зафиксировать численную ошибку до усложнения.
5. Повторить для состояния поверхности и пригодностей. Разделить правила по версии игры.

## Полнота гонки

- Реальные сегменты трассы: прямые, повороты, уклоны, внутренняя/внешняя дорожка, длина пути и бонусы.
- Позиционный AI, position keep, lanes, блокировки, обгоны, kakari и другие состояния.
- Полная грамматика условий, история состояния и случайные интервалы активации.
- Эффекты навыков на себя/соперников, предикаты порядка, повторные активации, cooldown, уровни и уникальные способности.
- Численные правила высоких статов и актуальные механики конкретной Global-версии.

## Редактор и аналитика

- Варианты персонажей/костюмов, звёзды, полный набор пригодностей и уникальные навыки соответствующего варианта.
- Библиотека билдов, несколько сценариев гонок, восстановление полных сценариев JSON.
- Пакетные прогоны с распределениями результатов, сравнением билдов и доверительными интервалами.
- Сохранение версий локального справочника для повторения старых экспериментов.
- Упаковка самостоятельного приложения Windows после стабилизации правил.

## Критерий точности

Требуется набор независимых эталонов по версиям игры, известным входам и механикам с опубликованными погрешностями. Целевые допуски задаются после определения точности самих эталонов. Декларация «100% точности» по одной совпавшей гонке недопустима.

## Статус 0.2

Реальная геометрия/вращения/рельеф, совместное поле, повышенные статы, уровни и функциональное подключение обычных навыков реализованы. Часть сложных условий приближена. Шаг извлечён из metadata. Следующий критерий завершённости — независимые игровые эталоны, измерение ошибок и проверка RNG/порядка операций; текущая реализация не закрывает критерий точности.
