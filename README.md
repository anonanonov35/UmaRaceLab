# Uma Race Lab 0.4.1

[English](README_EN.md) · [Подготовка GitHub и сборка Windows](docs/GITHUB_RELEASE.md)

Локальный симулятор Umamusume: Pretty Derby для Windows. Основной критерий проекта — проверяемая точность.

**Совпадение с игрой пока не измерено. Функциональный охват навыков не означает доказанного совпадения с нативной логикой.**

## Запуск

**Готовая Windows x64 сборка:** распакуйте `UmaRaceLab-0.4.1-windows-x64.zip` целиком и запустите `UmaRaceLab.exe`, сохранив рядом папку `_internal`. Python/Tk и Node.js уже включены. Выберите `master.mdb` собственной установленной Global-версии игры. Настройки и билды релизной сборки находятся в `%LOCALAPPDATA%/UmaRaceLab`; старые билды импортируются кнопкой «Загрузить билды» из папки прежнего проекта.

Откройте `Start Uma Race Lab.cmd` или выполните `./run.ps1`. Используются Python 3.11+ с Tk и Node.js; на этом ПК оба доступны. Интернет для обычного запуска не нужен. Свой Python задаётся через `UMA_LAB_PYTHON`.

Для запуска **из исходников на другом ПК** установите `pip install -r requirements.txt`, один раз выполните `python tools/prepare_release_deps.py`, затем запустите `python -m uma_lab`. Подготовка скачивает проверенные runtime-зависимости, а не файлы игры. Исходники для GitHub и бинарные архивы не содержат личных билдов или игровых данных.

По умолчанию игра читается из `D:/SteamLibrary/steamapps/common/UmamusumePrettyDerby`. Другой master.mdb можно выбрать в приложении. Игровые файлы открываются только для чтения.

В правом верхнем углу доступны **RU / EN**. Выбор сохраняется и применяется ко всем экранам, диалогам, схемам и пояснениям. Названия и описания навыков из игры, имена персонажей и пользовательских билдов сохраняются как в исходных данных. Переключение языка сохраняет текущую гонку, позицию повтора и несохранённые правки формы. Открытый диалог сначала нужно закрыть.

Интерфейс 0.3 использует графитовую навигацию, светлые поверхности и оранжевые акценты по предоставленному референсу. При небольшой высоте окна включается компактная компоновка. Расчётная модель остаётся `contested-local-0.2.2`.

Рядом с RU / EN есть переключатель **«Тёмная тема» / «Светлая тема»**. Выбор сохраняется. Тема применяется к рабочим экранам, таблицам, редактору, справочнику и схемам трассы; сохраняет ввод, рассчитанную гонку, позицию повтора и настройки языка. Системные окна Windows используют оформление операционной системы.

## Редактор билдов

Введите имя билда и выберите конкретную версию, например **Oguri Cap [Starlight Beat]** или **Oguri Cap [Ashen Miracle]**. Собственный уникальный навык закрепляется автоматически по связям `card_data → card_rarity_data → skill_set → skill_data` из подключённой базы. Выбор звёзд учитывает смену уникального навыка при повышении редкости; его уровень 1–6 вводится отдельно.

Пять характеристик вводятся вручную. Ниже доступны все десять пригодностей: Turf/Dirt, Sprint/Mile/Medium/Long и Front/Pace/Late/End. При выборе другой версии подставляются её базовые пригодности из игры; затем измените их до значений своего выращенного билда. Расчёт выбирает ячейки по трассе и стратегии. Смена версии сохраняет введённые характеристики.

Карточки навыков расположены в две колонки: уникальный — с многоцветным градиентом, золотой — на золотом фоне, обычный и унаследованный — на белом. Тип подписан текстом. Двойной щелчок или Enter открывает описание. Собственный уникальный навык нельзя удалить; другие уникальные навыки добавляются в их отдельной унаследованной версии. Выбор новой ступени одной группы заменяет предыдущую. Золотые и обычные навыки добавляются вручную из справочника.

Старые JSON-билды читаются. Версия определяется по сохранённому `outfit_id`, затем по собственному уникальному навыку, иначе выбирается базовая версия указанной умы. Собственный уникальный навык приводится в соответствие выбранной версии. Прежние три пригодности сохраняются и заполняют соответствующие строки полной таблицы, пока вы не измените их. Исходный файл не перезаписывается при одном лишь открытии. Записи с отсутствующей версией нужно исправить до запуска гонки.

## Возможности

- Совместное поле 1–18 участниц: полосы, блокировки, удержание позиции, обгоны, kakari, выносливость, рывок, борьба и сохранение силы.
- Пять характеристик 1–5000. Значения выше 1200 участвуют в формулах с обработкой избытка; у пассивов, настроения и бонусов трассы отдельные этапы применения. Диапазон ввода не означает, что каждый такой билд доступен в игре.
- 734 записи навыков из локальной базы. 732 обычные записи проходят аудит типов эффектов и языка условий. Уникальные, унаследованные, обе ветки, предусловия, уровни и зависимые от билда множители участвуют в модели. Часть сложных предикатов пока приближена и отмечена в справочнике. Две записи Carnival Bonus относятся к сценарным эффектам 501–503: их расчёт явно блокируется.
- Динамические длительности по оставшемуся HP, отставанию и обгонам; дополнительные эффекты от обгонов/других навыков; учёт cooldown и нескольких all_corner_random точек. Эти механизмы ещё требуют сверки с игровыми кадрами.
- 119 проверенных геометрий из 121 записей базы. Настоящий контур сверху и профиль высот, реальные длины поворотов и игровые уклоны. Обе схемы показывают early race, mid race, late race, last spurt. Фактический финишный рывок каждой участницы хранится отдельно от меток дистанции.
- Поправка фактического пути при внешней полосе на повороте и при смене полосы, по реальным координатам и вращениям CourseLaneAnim.
- Пауза, перемотка, 1×/4×/16×, события и результаты. Время победителя в формате `1:29.9`, отставания от предыдущей участницы (Nose, Head, Neck, доли L); пока с отметкой ≈ для невосстановленных порогов округления. Расчётные времена и два разрыва в секундах открываются флажком. Кнопка «Как читать результаты» объясняет текущий прогон.
- Вариант и звёзды выбираются в редакторе; популярность, команда, поклонники, победы и суммы статов Aoharu — в дополнительных параметрах навыков.
- Автосохранение билдов и JSON-экспорт прогона с хешем базы, WASM, параметрами, геометрией и телеметрией каждого внутреннего шага.

Две записи трасс без необходимых локальных ресурсов не заменяются вымышленной геометрией. После изменения индекса ресурсов каталог строится заново при следующем расчёте. Неизвестные условия или эффекты блокируют запуск.

## Источники и точность

Основа расчёта — открытый `honse-sim` 0.13.0 с локальными исправлениями. Исходники, лицензия и собранный WASM находятся в `vendor/honse-sim/`. Это открытый код сообщества, а не декомпилированный код Cygames.

Из собственной установки прочитаны master.mdb, геометрия CourseLaneAnim, события трасс и race parameter definitions. Из стандартных метаданных подтверждён шаг симуляции `0.066600002348423` с. Тела нативных функций полностью не восстановлены.

Границы доказательности, известные приближения и процедура сравнения: [docs/ACCURACY.md](docs/ACCURACY.md). Результаты анализа: [docs/RESEARCH_V2.md](docs/RESEARCH_V2.md). История: [MODLOG.md](MODLOG.md).

## Проверка и сборка

```powershell
python -m unittest discover -s tests -v
python tools/smoke_ui.py
python tools/smoke_ui_localization.py
python tools/smoke_ui_theme.py
python tools/smoke_ui_builder.py
python tools/validate_local_model.py
```

Проверки UI и validate_local_model требуют собственной установленной игры. Проверка локализации также использует копию local/autosave-builds.json. Результаты и снимки находятся в игнорируемом `local/`. Это проверки работоспособности, охвата и инвариантов; они не заменяют игровой эталон. Решения по дизайну и локализации: [docs/UI_DESIGN.md](docs/UI_DESIGN.md).

Для изменения Rust/WASM: `tools/prepare_rust.py`, `tools/prepare_wasm_bindgen.py`, затем `tools/build_engine.ps1`. Обычный запуск использует уже включённую сборку. Данные для геометрии извлекает `tools/build_course_catalog.py`; нужны локальные UnityPy, SQLite3MultipleCiphers и публичные исходники формата, описанные в `THIRD_PARTY.md`. На этом ПК инструменты уже подготовлены в `.local/`.

Игра, её данные и извлечённые ресурсы не распространяются вместе с проектом. Ничего не опубликовано.

Для диагностики Kyoto #10804 с сохранёнными билдами: `python tools/diagnose_kyoto_clock.py --runs 24`. Это проверка моделей часов, а не подгонка скорости под игровой диапазон.

Момент финиша уточняется внутри шага движения; при пересечении линии в одном шаге порядок определяется этим временем. Локальный enum `HorseLength` и коэффициент `DIFFTIME_TO_LENGTH` читаются из metadata игры. Границы категорий, точное округление и использование scaled-разницы в нативной цепочке пока не восстановлены. Экспорт разделяет исходные разрывы и приблизительную подпись. Проверить локальные константы: `python tools/inspect_finish_rules.py` (отчёт вне репозитория).
